## 1. 채택한 시각 방향

**계기판 (Instrument panel).** 근단색 그래파이트 표면, 1px 헤어라인, 2px 라운드, 기계값 전용 모노스페이스, 액센트는 상태 표시에만 사용.

- 서체: Pretendard (한글 UI 표준, P0는 한국어 전용 · i18n은 P1) + JetBrains Mono (채널·역할·시각·권한 상수·명령어)
- 액센트: `#4A5A8C` (라이트 테마 `#3F5185`) — 슬레이트 블루. 계측기 계열이며 Discord 브랜드 색과 혼동되지 않음
- 그림자 없음. 깊이는 선 1단계 + 표면 색 1단계로만 표현
- 테마: 다크 canonical, 라이트는 동일 토큰의 값 교체

근거: 제품 성격이 "조용한 보존 유틸리티"이므로 화면은 기록을 읽는 표면이어야 하고, 크롬은 존재감을 최소화해야 한다. 인기 순위·감시 로그·AI 마법·크리에이터 이코노미 어느 쪽으로도 읽히지 않는 시각 언어가 필요했다.

## 2. 검토했으나 기각한 방향

| 방향 | 내용 | 기각 이유 |
|---|---|---|
| 판 (Panel) | 슬레이트 액센트를 적극 사용, 카드 크롬 제거, 10px 라운드, 15px 본문 | 가독성은 가장 좋았으나 일반 SaaS 대시보드에 가까워져 "의도적으로 작은 범위의 도구"라는 성격이 흐려짐 |
| 유리 (Glass) | 절제된 반투명 + blur 1단계, 틴트 배경 | 사용자 요청으로 실제 제작 후 비교. 메타데이터 대비 손실이 크고 장식적으로 읽힘. Discord 자체도 blur를 쓰지 않음 |
| 지브라 행 틴트 | 목록 행을 교대로 2% 밝게 | 클립 행은 높이가 균일하지 않음(코드 블록·첨부가 있으면 3배). 교대 틴트가 리듬이 아니라 임의의 블록으로 읽혀 기각. 헤어라인 단독 유지 |
| 소스 채널별 틴트 | 채널마다 다른 틴트 | 채널 수 상한·색 배정·접근성 문제를 새로 만들어 P0 범위 밖으로 판단 |

## 3. 디자인 과정에서 교정한 판단

- **흰 캔버스 착시:** 초기 비교에서 유리 방향이 "섹션 구분이 잘 된다"고 보였으나, 실제 원인의 절반은 비교용 흰 배경이었다. 각 방향을 자기 페이지 배경 위에 다시 올려 비교한 뒤 판단이 바뀜. → 시안은 항상 실제 페이지 배경에서 검증한다.
- **접근성 결함 수정:** muted 텍스트 토큰이 WCAG AA 미달(4.0:1)이었다. `#6e737a → #83888f`, `#71767f → #7e838c`로 조정해 4.6:1 이상 확보. 비활성 컨트롤은 의도적으로 3:1 미만 유지.
- **faint 토큰 오용 방지:** `faint(#5f646a)`는 비활성 컨트롤 전용으로 용도를 한정했다. 플레이스홀더·조건 라벨·주석 등 의미를 가진 텍스트에는 `muted(#83888f, 5.37:1)`를 사용한다.
- **상태를 색만으로 전달하지 않음:** 모든 상태 표시에 텍스트 태그(`NOTE` / `OK` / `확인` / `오류` / `누락`)를 선행시킴.

## 4. 컴포넌트 라이브러리 선택

shadcn/ui 등 기성 라이브러리는 구현 속도에 도움이 되지만, 기본값을 그대로 쓰지 않고 위 토큰(표면 4단·선 3단·글자 4단·의미 4색, 4px 간격 배수, radius 2px, 그림자 없음)으로 정규화해 사용한다. 필요한 컴포넌트는 P0가 실제로 쓰는 범위로 한정: 버튼 4변형, 입력/셀렉트/역할 다중 선택, 라디오·체크박스, 배지, 상태 콜아웃, 토스트, 클립 카드, 페이지 헤더, 필터, 페이지네이션, 빈/로딩/오류/세션 만료 상태, 파괴적 동작 확인.

## 5. 카드 시각 위계 (고정)

① 출처(작성자·채널·원본 시각) → ② 메시지 본문 → ③ 답장 맥락 → ④ 보관 시각 → ⑤ 동작(secondary 1개).

반응 수·좋아요·순위 표시는 카드에 존재하지 않는다. 원본 메시지의 봇 반응(📎)은 "아카이브가 존재함"이라는 신호이며 인기 지표가 아니므로 웹 아카이브에 수치를 노출하지 않는다.

## 6. 카피 원칙 (한국어 P0)

1. 결과를 먼저, 이유는 짧게 — "채널을 선택해야 저장할 수 있습니다."
2. 내부 용어 비노출 — canonical clip / tombstone / PENDING 등은 UI에 등장하지 않음
3. 과장 금지 — "어떤 데이터도 저장하지 않습니다"가 아니라 "메시지 사본이 아니라 운영 정보를 저장합니다"
4. 파괴적 동작은 결과를 문장으로 — 삭제/유지 항목을 나열한 뒤 명시적 체크박스 확인

## 7. 디자인 중 발견한 제품/범위 이슈

- **관리 화면 분리:** 브리프는 화면 B와 E를 합칠 수 있다고 했으나, 최초 설정(1회, 결과를 읽어야 하는 흐름)과 현재 설정 열람+데이터 삭제(반복 방문, 파괴적 동작 포함)는 목적이 달라 2개 화면으로 분리했다.
- **기존 채널 사용의 노출 결과:** 기존 채널을 고르면 그 채널을 볼 수 있는 모든 멤버가 아카이브를 볼 수 있다는 사실을 선택 지점에 인라인으로 명시했다. 보안 문서를 읽지 않아도 신뢰 결과가 전달되어야 한다는 요구를 충족한다.
- **목록 누락 상태의 정보 잔존:** Discord 측 사본이 삭제된 경우에도 보관 기록(작성자·채널·시각)은 남으므로, "원본 없음"이 아니라 "보관된 사본을 찾을 수 없음 + 기록은 남아 있음"으로 문구를 분리했다.
- **설정 링크 만료 화면:** 만료 이유(일회용·15분)와 복구 경로(`/setup` 재실행)를 함께 제시하고, 이미 설정을 마친 서버라면 링크 없이도 동작한다는 안심 문구를 추가했다.

## 8. 반응형 · 접근성

- 컨테이너: 아카이브 720px, 설정 폼 560px, 복구 화면 420px, 페이지 최대 1120px
- 640px 이하: 필터·페이지네이션 세로 적층, 카드 패딩 16→12. 960px 이하: 설정 2열 → 1열
- 포커스 링 전 컴포넌트 공통(액센트 2px + offset 2px), 본문 최소 13.5px / 라벨 최소 11px, 한글 본문 line-height 1.65 이상
- 긴 코드·URL은 `pre` 내부 가로 스크롤로 격리해 카드 폭을 넘기지 않음

## 9. 마감 때문에 의도적으로 남긴 미완성

- 라이트 테마는 핵심 표면·버튼·입력·콜아웃만 검증했고 전 컴포넌트 매트릭스는 만들지 않았다
- 애니메이션은 정의하지 않았다(로딩은 정적 스켈레톤 + 텍스트 고지)
- 일러스트레이션·마케팅 페이지·아이콘 세트 없음. 첨부 미리보기는 플레이스홀더
- 워드마크는 라틴 "Clip" 단일 표기. 한글 병기 및 제품명 확정은 P1
- 스크린리더 안내(aria-live) 문구는 구현 단계에서 확정 필요
